# Build guide

## Windows EXE (.NET 8, WPF)

Prereqs: [SDK .NET 8](https://dotnet.microsoft.com/download/dotnet/8.0). The daemon
jar ships next to the EXE — build it first (needs Android SDK only for `d8`).

```powershell
# 1) input daemon (DEX jar)
cd android
.\gradlew.bat :daemon:dexJar          # → android/daemon/build/libs/vjc-daemon.jar
copy daemon\build\libs\vjc-daemon.jar ..\desktop\tools\daemon\vjc-daemon.jar
cd ..

# 2) desktop app
dotnet build JoyLiveEX.sln -c Release
dotnet publish desktop\src\VirtualJoyCon.DesktopApp\VirtualJoyCon.DesktopApp.csproj `
  -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true -o publish\VirtualJoyCon

# 3) (optional) self-host relay
dotnet publish desktop\tools\VjcRelay\VjcRelay.csproj -c Release -r win-x64 `
  --self-contained true -p:PublishSingleFile=true -o publish\VjcRelay
```

If `vjc-daemon.jar` is missing, the app still builds/runs — USB global-gamepad mode is
simply reported unavailable until it's placed at `desktop/tools/daemon/`.

## Android APK (companion + daemon)

Prereqs: JDK 17, Android SDK platforms;android-34 + build-tools;34.0.0
(Android Studio handles all of it).

```bash
cd android
./gradlew :app:assembleDebug            # debug APK (installs everywhere)
./gradlew :app:assembleRelease          # release APK (unsigned → debug-signed below)
./gradlew :daemon:dexJar                # vjc-daemon.jar (shipped inside app assets? no — PC pushes it)
./gradlew :app:testDebugUnitTest        # protocol vectors
```

Signing for real distribution:

```bash
keytool -genkeypair -keystore vjc-release.jks -alias vjc -keyalg RSA -keysize 2048 -validity 10000
# env vars consumed by app/build.gradle.kts:
VJC_KEYSTORE=... VJC_KEYSTORE_PASSWORD=... VJC_KEY_ALIAS=... VJC_KEY_PASSWORD=...
```

Without the env vars the release build falls back to the debug keystore so CI always
produces an installable `VirtualJoyCon-Android.apk` (clearly labeled in the release
notes generated by the workflow).

min/target SDK: 26 / 34. No Play Store compliance work included (sideloading is the
distribution assumption of this project).

## GitHub Actions

`.github/workflows/build.yml` runs on every push:

1. `tests` — `dotnet test` (protocol vectors) + `:app:testDebugUnitTest`;
2. `daemon` — builds `vjc-daemon.jar` with `d8` (ubuntu + SDK);
3. `windows` — self-contained single-file publish, zips into **`VirtualJoyCon-Windows.zip`**
   (EXE + optional `relay/` + PT BR instructions);
4. `android` — assembles both APKs, renames to **`VirtualJoyCon-Android.apk`**
   (+ `-debug`), uploads;
5. `release` — on `main`, creates a **draft GitHub Release** with the artifacts.

Secrets (all optional): `VJC_KEYSTORE` (base64 jks), `VJC_KEYSTORE_PASSWORD`,
`VJC_KEY_ALIAS`, `VJC_KEY_PASSWORD`.

## Tests worth knowing about

- `desktop/tests/VirtualJoyCon.Core.Tests` — PBKDF2/session-id/STATE golden vectors,
  packet codec round-trip, AES-GCM tamper rejection, full VjcLink handshake over an
  in-memory pump, stick curve math, hat encoding.
- `android/app/src/test/.../ProtocolVectorTest.kt` — the same vectors against the
  Kotlin mirror. Divergence between the two suites = protocol break on a real device.
